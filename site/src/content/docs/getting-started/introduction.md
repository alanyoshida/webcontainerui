WebContainerUI is a multi-user portal that delivers full Linux desktops and command-line coding agents inside the browser. Each person signs in with their own account, picks an item from the catalog and gets a container of their own, reached through the same origin as the portal, with no client to install.

The back end is FastAPI (Python 3.12), the front end is React with Vite, persistence is handled with SQLAlchemy (SQLite in development, PostgreSQL in production) and each instance is a Docker container on an internal network.

## What the catalog offers

The catalog holds two kinds of entry, both used through the same session mechanism.

### Linux desktops

These are the [webtop](https://docs.linuxserver.io/images/docker-webtop/) images from LinuxServer.io, registered by download (`pull`). A new deployment starts with four entries, downloaded in the background on first startup:

| Entry | Image |
|---|---|
| Webtop XFCE | `lscr.io/linuxserver/webtop:latest` |
| Ubuntu KDE | `lscr.io/linuxserver/webtop:ubuntu-kde` |
| Alpine MATE | `lscr.io/linuxserver/webtop:alpine-mate` |
| VS Code | `lscr.io/linuxserver/vscode:latest` |

The administrator can register other images, edit resource limits (memory, CPU, shared memory), set the forwarding port, disable an entry without removing it and upload a cover image.

### CLI coding agents

These are images built locally by the portal itself, each exposing a web terminal ([ttyd](https://github.com/tsl0922/ttyd)) that opens straight into the corresponding tool:

| Entry | Tool | Command |
|---|---|---|
| Claude Code | Claude Code | `claude` |
| Hermes | Hermes Agent (Nous Research) | `hermes` |
| Agy | Antigravity CLI | `agy` |
| OpenCode | OpenCode | `opencode` |
| oh-my-pi | oh-my-pi | `omp` |

Build details are in [Agent images](/architecture/agent-images/).

## What the user does

- Sees in the catalog only the ready images their groups have access to.
- Starts, opens, stops, updates and deletes their own instances. Each user keeps at most one instance per image.
- Uses the session in a dedicated view of the portal, with a full-screen option.
- Keeps files between runs: each user and image pair has its own volume, preserved when the instance is stopped and removed only when the instance is deleted, after confirmation.
- Has their own SSH identity, generated by the portal and available in all their instances, so that `git` inside the container authenticates with remote repositories without manual setup.

Idle instances are stopped automatically (after 30 minutes by default), so that abandoned sessions do not consume host memory.

## What the administrator does

- **Users and groups**: creates accounts, disables them without deleting and organizes people into groups. There is no self-registration.
- **Access grants**: permission to use an image is given to groups, never to individuals. Revoking a grant immediately stops the affected instances, and the impact is shown before confirmation.
- **Catalog**: registers images, follows the download or the build, edits limits and covers.
- **AGENTS.md library**: maintains `AGENTS.md` documents and links each catalog entry to at most one of them; the text is injected into instances as `/config/AGENTS.md`.
- **MCP servers**: registers Model Context Protocol servers and links them to agent images; the configuration reaches instances without rebuilding the image.
- **Skills**: maintains a library of skills and links them to agent images; the link triggers a rebuild of the image, which installs the skills.
- **Usage metrics**: sees running instances and the run history, with hours per user and per group, most-used images, termination reasons, daily usage and peak concurrent instances.

The behavior of each of these areas is formally specified; the index is in [Capabilities](/reference/capabilities/).

## Before deploying

:::danger[The portal is equivalent to root on the host]
The portal process needs the Docker socket to create containers, and whoever can create a container can mount the host's file system. In addition, the user has root inside their own desktop: the webtop images ship a terminal with passwordless `sudo`. Treat a session like an SSH login to a machine on your network, and do not expose the portal to the internet without strong authentication in front of it.
:::

Read [Trust surface](/security/trust-surface/) and [Isolation layers](/security/isolation-layers/) before exposing the portal beyond your own machine.
